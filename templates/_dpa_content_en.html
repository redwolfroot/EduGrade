Parties and conclusion

Controller: the user of EduGrade and – where they use EduGrade for a school – the school or school authority on whose behalf they act.

Processor: Fabian Murauer, avocloud.net, Rablstraße 23a/4.4, 4600 Wels, Austria – fabian.murauer@avocloud.net

The agreement is concluded electronically (Art. 28(9) GDPR): the controller signs it with their name in a separate step before first using EduGrade. Name, school (if any), time and contract version are stored in the account. A material change to the agreement requires signing again.

If a teacher uses EduGrade for their school, by signing they confirm that they are authorised to do so or have agreed the use with the school management. Schools that need a separately signed agreement can request one by email.

1 Subject matter and duration

The subject matter of this agreement is the provision of the web-based grade management system EduGrade (storage, synchronisation and retrieval of the data entered by the controller) by the processor.

The agreement applies for the lifetime of the user account. It ends automatically when the account is deleted.

2 Nature and purpose of processing

The processor stores the controller's data in encrypted form and makes it available for retrieval and editing. The sole purpose is the keeping of grades, assessments, attendance and participation records by the teacher.

No processing takes place for the processor's own purposes (e.g. analysis, advertising, disclosure).

3 Types of data and categories of data subjects

Data subjects: students and teachers recorded in EduGrade by the controller.

Types of data:

  • Student names, class and subject assignment
  • Grades, assessments and related notes
  • Attendance, participation and behaviour notes
  • When using an organisation: student name, class and teacher name in the organisation-wide student list
  • When using the WebUntis integration: credentials and timetable data retrieved with them

Special categories of personal data (Art. 9 GDPR) should not be recorded.

4 Instructions

The processor processes the data only on documented instructions from the controller. Using the functions of EduGrade (entering, changing, exporting, sharing, deleting) in particular counts as an instruction. If the processor considers an instruction to be unlawful, it informs the controller without delay.

Processing without instruction only takes place where the processor is legally obliged to do so; in that case it informs the controller beforehand unless the law prohibits this.

5 Obligations of the processor

  1. Confidentiality: All persons with access to the systems are bound to confidentiality.
  2. Security: The processor takes the technical and organisational measures pursuant to Art. 32 GDPR set out in annex 1.
  3. Sub-processors: Only the sub-processors listed in annex 2 are used. The processor announces planned changes at least 30 days in advance in the app or by email; the controller may object and in that case delete the account.
  4. Data subject rights: The processor supports the controller with access, rectification, erasure, restriction and data portability. The controller can fulfil most of these rights directly in the app (edit, export, delete).
  5. Data breaches: The processor notifies the controller of personal data breaches without undue delay after becoming aware of them, by email to the account address, with the information under Art. 33(3) GDPR as far as known.
  6. Assistance: The processor assists the controller with data protection impact assessments and prior consultations (Art. 35, 36 GDPR) within the information available to it.
  7. Place of processing: Processing takes place exclusively within the European Union.

6 Audit rights

The processor makes available to the controller all information necessary to demonstrate compliance with this agreement and allows for audits. These are primarily carried out by written information; on-site inspections are possible with reasonable notice and without disrupting operations.

7 Deletion and return

The controller can retrieve their data at any time using the export function. When the account is deleted, all of the controller's data is deleted without delay. Backup copies are overwritten as part of regular rotation after 30 days at the latest.

8 Liability and final provisions

Liability is governed by Art. 82 GDPR. Austrian law applies. Changes to this agreement are announced in the app; the current version is available at /avv. Should any provision be invalid, the remainder of the agreement remains effective. In case of doubt, the German version prevails.

Annex 1 – Technical and organisational measures (Art. 32 GDPR)

EncryptionAll gradebook data is stored encrypted with AES-256-GCM. The key is derived from the teacher's password (PBKDF2) and is not stored permanently on the server; it is only available in memory during an active session. Without the teacher's password or recovery key the data cannot be decrypted. The server sees the password at sign-in and keeps the key in memory during the session; without an active session the data cannot be decrypted by the operator either.
ExceptionsNot encrypted with the teacher's key are: (1) class shares for students/parents and class handovers to other teachers – these are encrypted with a server key so recipients can open them without the teacher's password. The share entry additionally contains names, class, teacher name and the PIN hashes in plain form; the snapshot also includes notes and participation (not the behaviour log). Handovers are deleted on acceptance, decline or expiry; (2) when using an organisation, student name, class and teacher name for the organisation-wide student list (no grades); (3) the account's school name.
TransportHTTPS/TLS only. Emails are sent via our own mail server using TLS (including certificate verification).
AuthenticationPasswords as salted PBKDF2 hashes; optional passwordless sign-in via a paired smartphone; sessions with secure httpOnly cookies and limited lifetime; rate limiting against brute-force attacks.
Access controlEach teacher can only access their own data. Only the operator has administrative server access; SSH access is key-based only (no password login), and administrative passwords are changed regularly.
Application securityCSRF protection, Content Security Policy, input validation, regular updates of the server software.
AvailabilityHosting in a data centre in Germany; regular backups of the encrypted database; export function for the teacher's own backups.
Data minimisationNo analytics, tracking or advertising services. Server logs with IP addresses are kept for at most 30 days.
DeletionDeleting the account removes all data immediately; backups are overwritten within 30 days.
